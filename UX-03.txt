# UX-03 Construction — Implementation Handoff

## Goal

건설 과정에서 불필요한 클릭을 줄이고, Belt / Pipe / 일반 건물의 조작 규칙을 최대한 통일한다.

핵심은:

> **Place → Connect → Fix** 흐름을 빠르고 예측 가능하게 만드는 것.

---

## 1. Farm Plot crop flow

Farm Plot을 설치하면 즉시 작은 Crop Picker를 띄운다.

예:

```text
Choose Crop

🍎 Apple
🧅 Onion
🍅 Tomato
🥔 Potato
```

Rules:

- Farm Plot 설치 직후 해당 Plot에 귀속된 picker 표시
- Crop 선택 후 picker 자동 닫힘
- 선택한 crop을 현재 Farm Plot build tool이 기억
- 이후 같은 tool로 Farm Plot을 연속 설치하면 이전 crop을 기본값으로 사용
- 필요하면 새 Plot의 picker에서 다른 crop으로 변경 가능
- Crop 미선택 상태로 Plot이 방치되는 경우를 최소화

목표는 기존의:

```text
Place Farm Plot
→ Exit build mode
→ Click Plot
→ Choose crop
```

흐름을 제거하는 것.

---

## 2. Pipe drag placement

Property Pipe를 Belt와 동일한 감각으로 바꾼다.

```text
Click + Drag
→ path preview
→ Release
→ place full pipe path
```

지원:

- 직선 drag
- 자동 90° 코너
- skipped-cell interpolation
- drag 중 valid/invalid preview
- release 시 유효 경로 일괄 설치

기존 한 칸씩 클릭하는 방식은 기본 interaction에서 제거한다.

---

## 3. Pipe path rules

Belt와 최대한 동일하게 동작하되 Property network validation은 유지한다.

권장:

- drag 시작점과 현재 pointer 사이에 grid path 생성
- 필요 시 한 번의 90° turn 사용
- 유효한 연결 방향 preview
- Processor property port에 닿으면 connection 가능 여부 표시
- invalid cell이 포함되면 해당 segment를 red preview

Property gameplay rule 자체는 바꾸지 않는다.

---

## 4. Placement tooltip

기존 generic failure:

```text
Placement requirements not met
```

같은 메시지를 player-facing UI에서 제거한다.

대신 validation 결과를 actionable reason으로 변환한다.

예:

```text
Farm Plot required here.
```

```text
Output cell is occupied.
```

```text
Outside purchased land.
```

```text
Cannot overlap another building.
```

```text
Collector must be placed on a Property Source.
```

```text
Pipe cannot connect from this side.
```

가능하면 항상:

> **무엇이 잘못됐는지 + 무엇을 바꿔야 하는지**

가 한 문장 안에서 이해되게 한다.

---

## 5. Tooltip position

Placement failure tooltip은 **마우스 커서 근처**에 표시한다.

이유:

- 플레이어 시선이 이미 placement preview에 있음
- Hotbar까지 시선을 이동할 필요 없음
- 어떤 cell이 실패했는지 즉시 연결 가능

Rules:

- pointer를 가리지 않을 정도로 offset
- 화면 경계를 넘으면 자동 reposition
- valid placement로 돌아오면 즉시 사라짐
- 긴 문장은 자동 크기 또는 wrap 처리

---

## 6. Build input consistency

공통 조작:

```text
Left Click
→ Place standard building

Left Click + Drag
→ Belt / Pipe continuous placement

R
→ Rotate current building/tool

Right Click
→ Cancel current build tool

Esc
→ Cancel current build tool / close active UI according to UX-01 priority
```

Normal Mode:

```text
Right Click
→ Remove building
```

우클릭 중 삭제 대상에는 UX-01 수정사항대로 **red outline preview**를 표시한다.

---

## 7. Belt / Pipe consistency

둘의 조작 철학은 동일하게 유지한다.

### Belt

```text
Drag
→ directional path
→ automatic corner
→ place on release
```

### Pipe

```text
Drag
→ property path
→ automatic corner
→ place on release
```

차이는 visual language와 validation뿐.

플레이어가 별도의 조작법을 다시 배울 필요가 없게 한다.

---

## 8. Property interaction

Property menu 관련 기존 input bug 수정과 충돌하지 않아야 한다.

Property tool active + pointer over world:

```text
→ world placement takes priority
```

월드 클릭 때문에 Property menu가 닫히면 안 된다.

Pipe drag 중에도 동일.

---

## 9. Connection preview

기계 배치 또는 Pipe/Belt drag 중 포트 연결 가능성을 간단히 표시한다.

예:

```text
✓ Ingredient input connected
✓ Property port connected
✕ Output missing
```

단 상시 checklist UI를 띄우지는 않는다.

추천 방식:

- 연결 가능한 포트 → subtle positive highlight
- 방향 불일치 → red/invalid highlight
- 실제 상세 텍스트는 invalid 상황에서만 tooltip

---

## 10. Repeated placement

일반 건물은 기존처럼 persistent tool을 유지한다.

즉:

```text
Select Cutter
→ Place
→ tool remains active
→ Place another Cutter
```

Farm Plot은 여기에 crop memory를 추가한다.

---

## 11. Out of Scope

UX-03에서는 다음은 다루지 않는다.

- full blueprint system
- advanced copy/paste
- undo
- item refund
- auto-routing complex pipe network
- multi-turn path editor
- final art polish
- bunny animation
- global warning system

---

## Acceptance Criteria

UX-03 완료 시:

- Farm Plot 설치 직후 crop을 바로 선택할 수 있음
- 선택 crop이 반복 Farm Plot placement에 기억됨
- Pipe를 click-drag로 연속 설치 가능
- Pipe가 자동 90° 코너를 지원
- drag 중 path preview가 보임
- invalid path segment가 명확히 구분됨
- generic placement failure text가 제거됨
- placement failure가 actionable reason으로 표시됨
- tooltip이 cursor 근처에 표시됨
- Belt / Pipe / Building의 cancel/rotate 규칙이 일관됨
- Property menu가 world placement 때문에 닫히지 않음
- 기존 Property network validation은 유지됨
