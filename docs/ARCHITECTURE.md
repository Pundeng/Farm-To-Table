# Cozy Food Factory implementation map

This document describes the current Unity **6000.5.2f1** implementation. The [Cozy Food Factory GDD](COZY_FOOD_FACTORY_GDD.md) describes intended rules; this map records what the repository currently does. `Demo.unity` is the only supported playable scene. Legacy Cleanup Phase 1 removed the Fantasy Rune Factory Prototype scene, its build entry, rune prefabs and objective assets, and its Editor setup tool. Phase 2A removed the remaining rune gameplay runtime and its exclusive tests. Phase 2B removed the inactive Prototype keyboard shortcuts and old group Move rollback path.

## Main campaign objective authoring

The single campaign configuration is the **Market** GameObject in [`Demo.unity`](../Assets/_Project/Scenes/Demo.unity): select it, then expand **Market → Main Campaign Objectives** in the Inspector. The array order is the play order. Each entry has a stable `Id`, player-facing `Display Name`, `Requirements` (each `Food` ID/kind/sell value and `Quantity`), and `Unlocks` (category/ID rewards). For example, change O1's Carrot requirement from quantity 30 to 40 directly in that Inspector array; no gameplay-code edit is needed. The small Market Inspector help box identifies missing entries, duplicate IDs, missing/invalid food, nonpositive quantities, and other incomplete order data. Runtime order validation still runs in `FoodOrderSequence`.

[`Market.cs`](../Assets/_Project/Scripts/Food/Market.cs) passes this serialized `FoodOrder[]` to [`FoodOrderSequence`](../Assets/_Project/Scripts/Food/FoodOrder.cs). The sequence tracks one active objective at a time, counts only deliveries after activation, grants each authored unlock on completion, and advances to the next array entry. The Market HUD and Recipe Book read that same sequence. Seed Shop offers and farmable regions are separate Market Inspector fields; a `region_access` reward, for example, opens eligibility to restore a region rather than restoring it automatically.

Save files store completed objective IDs in order, active objective ID, and active delivery counts by food identity. Chapter 1 deliberately replaces the obsolete five-objective campaign with O1-O8. The game now writes `cozy-food-factory-chapter-1.json`; the previous `cozy-food-factory-demo.json` remains untouched and is not offered by Load. Blueprints similarly use `cozy-food-factory-chapter-1-blueprints.json`, leaving old Property-numbered layouts untouched. This is an explicit new-campaign reset, not a migration of old prototype saves. Keep O1-O8 IDs and sequence positions stable after this release: changing an in-progress food or quantity can make saved progress fail validation (`ProgressionSaveService.ApplyValidated` expects the current requirement list and count to match).

Chapter 1's active Market orders are Carrot x30, Roasted Carrot x40, Tomato Sauce x70, Potato Slice x90, French Fries x150, Tomato Soup x220, Loaded Fries x300, and Garden Lunch x400. O1 grants Processor; O2 grants Basic Mixer, Tomato, and Onion; O3 grants Cutter and East Field access; restoring East Field grants Potato. O8 grants the `chapter:vegetable_complete` completion key. Normal Property construction offers Heat after O1 and Water after O5; Time and Cold sources remain authored but unavailable for Chapter 1 construction. The seven scene recipes are Carrot + Heat → Roasted Carrot, Tomato + Onion → Tomato Sauce, Potato → 2 Potato Slices, Potato Slice + Heat → French Fries, Tomato Sauce + Water → Tomato Soup, French Fries + Tomato Sauce → Loaded Fries, and Loaded Fries + Tomato Soup → Garden Lunch. Apple remains a separate Farm Plot crop; Basil is absent from Chapter 1. Chicken Village, Egg, and trade are not implemented.

## UX-07.01 visual foundation

Each Build Menu `BuildingDefinition` keeps its gameplay footprint separate from presentation. In the Demo scene's Building Placement options, assign `Visual Sprite` for a single body image or `Visual Prefab` for a body with optional moving parts; the prefab takes precedence. `Visual Scale` and `Visual Offset` are presentation-only: scale multiplies the body, and offset moves it in grid-cell units. `Visual Sorting Offset` is limited so placed bodies stay below ports, UX-02 feedback, selection outlines, and preview overlays. The existing colored geometric body remains when neither asset is assigned. By default the body rotates with the building; `Keep Visual Upright` counter-rotates the artwork only. L-shaped Processor artwork needs a transparent unoccupied corner, and Harvester artwork needs transparency over its Farm Plot. Its existing body alpha remains in effect. A visual prefab can contain later animated parts and a Bunny anchor under its static body; ports and diagnostics remain siblings outside the visual root. Animation should read machine state and never drive processing time.

Assign food Sprites by stable food ID in the Belt Transport Coordinator's `Food Visuals` list. The same lookup works for transported food restored from a save because the saved ID is retained. Missing entries or Sprites use the existing color/shape/label fallback; new food content remains visible without art. Close and Medium can show assigned Sprites; Far uses a small neutral mark and hides identity text unless hovered, selected, or diagnostically emphasized. Property Source, Collector, and Pipe Sprites are optional on Building Placement's `Property Visuals`; their connection tint and status overlays remain authoritative. The fixed Market has its own optional body Sprite and retains its input markers. Sprite import pivots should be centered; body images should be authored for the configured footprint and verified at all four rotations and all three camera information levels. Final art, animation clips, Bunny poses, and a final pixel-density/palette standard are still pending.

## UX-07.02 machine state animation

`MachineVisualAnimator` adds one `Animated Parts` child under the UX-07.01 visual root after placement. It reads existing Farm Plot growth, Harvester output count and mature crop changes, Processor/Cutter states, and Mixer output presence in `LateUpdate` before belt transport consumes ready output; it never writes gameplay state. Farm crop scale follows elapsed growth or mature inventory. Processor motion uses the existing UX-02 working decision so paused Property supply stays still; Cutter motion runs only while both outputs are available. Mixer has no processing interval, so output creation or its existing output-release event text starts a brief turn instead of a continuous working loop. Harvest observations, completed output transitions, and Market's existing delivery event start short reactions once; loaded/initial output does not. Collector activity reads existing source connection, capacity, and connected consumer status. Pipes stay static. All visual children sit below ports and UX-02 diagnostics, and the gameplay transform and port markers do not move.

Close shows the supported motion; Medium retains the primary motion; Far hides decorative animated children unless a placed building is hovered, selected, or diagnostically emphasized. State observation continues while hidden, so returning to Close does not replay an old reaction. The Market and Collector hide their small reactions at Far. Prefab or Sprite body art can replace the static body while the `Animated Parts` child remains independent; later Animator or Sprite animation can replace that child without changing processing. Final art, Bunny attachment, and authored animation clips remain pending.

## UX-06 factory scale

`BlueprintLibrary` persists version-1 named construction layouts in a separate file under `Application.persistentDataPath`. Records use stable building definition IDs, relative positions, rotations, optional Farm Plot crop IDs, and Property connection types. Fixed sources, generated Processor demands, runtime food/buffers, and progression are omitted. Unsupported library versions remain untouched and read-only; individual incompatible records remain in the file and are shown as unavailable. The Build Menu operates on the library without replacing the temporary Clipboard. Placement resolves definitions in the current scene and uses the existing complete group preview and Demo group validator. Property planning uses a preview network and can remap copied connections to a matching destination source. Failed group commits remove any newly placed parts and retain the source selection.

`ConstructionHistory` keeps 50 in-memory construction deltas. The controller captures construction-only layouts around one building action, one Belt/Property/right-removal drag, crop selection, and group paste or move. Undo/Redo checks the expected current parts, active runtime state, dependencies, current unlocks, and the full prospective scene snapshot before replay. Rejected replay leaves its stack entry in place. New successful construction clears Redo; a scene reload creates a fresh history. History is absent from progression saves. Group movement reuses the cut/paste transaction while leaving Clipboard data intact. Single click, Shift click, and Shift rectangle selection use the existing footprint and overlay-aware selection model. The current Demo transaction keeps source registrations alive until destination placement succeeds, so relocation into cells occupied by the moving group is rejected. Supporting overlapping relocation requires reversible detach and reattach across Farm Plot, Harvester, Processor, Mixer, Cutter, Belt, and Property registrations; it has not been implemented without Unity lifecycle verification.

`FactoryCameraController` exposes Close, Medium, and Far information levels over its existing zoom range with hysteresis and an interruptible camera jump. Placed Belt labels and food marks, plus port labels, respond to zoom; hover, selection, and emphasized UX-02 diagnosis restore detail. Preview visuals and selected outlines remain visible at any zoom. `FactoryIssueTracker` observes the existing `MachineFeedbackResolver` result after its UX-02 priority choice, stabilizes Needs Property, Invalid Recipe, and Output Blocked warnings, and excludes ordinary Needs Input. A compact HUD button opens an Issues panel; a selected issue closes the panel, pans to the machine, and reuses its port emphasis, local trace, and action tooltip. The list updates when a problem resolves.

UX-06 playtest follow-up: the selected-count HUD has a small Save Blueprint action that opens the Build Menu's Blueprint Library save form. The Library shows an empty-state explanation and labels its save and placement actions. The Demo camera ranges from 3 to 20 orthographic units, with Medium and Far thresholds at 7 and 13 plus hysteresis. At Far, placed Belt food marks are much smaller and neutral rather than carrying food identity color/shape; ordinary labels are hidden. The controller still lets hover, selection, and UX-02 emphasis restore detail. Active-item group movement remains blocked: current source building and transport/Property registrations are torn down by deferred Unity destruction, while the group transaction has no reversible detach for every Demo building type. It cannot promise both full rollback on a failed commit and immediate discard after a successful one without changing that lifecycle.

## UX-05 recipe experience

`RecipeDiscoveryRegistry` still records only the first actual production of a Processor, Mixer, or Cutter recipe. It now tracks unseen discovered identities separately. The Recipe Discovery card uses the shared food color and label from Belt visuals and presents ingredient, Property, machine, output, and Book confirmation. If order completion and recipe discovery are both pending, the discovery modal displays first and the UX-04 order card waits. Neither viewing an order hint nor opening a Book category records discovery.

`RecipeDiscoveryPanel` builds its Book from the controller's authored Processing, Mixing, and Cutting recipes. All, Cutter, Processor, and Mixer filters show discovered names and summaries, current-objective hints with ORDER, and anonymous Unknown Recipe entries for unrelated future recipes. Current-order output and its manufacturing prerequisites are revealed recursively; that visibility does not change unlock or discovery state. Opening a discovered detail clears only that recipe's NEW indicator. Details follow authored inputs and Property; Cutter quantity comes from the paired-output process, Mixer inputs remain unordered, and raw ingredients lead to Farm Plot guidance. Prerequisite links use Back navigation. Clicking a working food machine opens the matching filter; a compact Recipes control beside a hovered problem machine gives the same access while its body click still emphasizes UX-02 port feedback. An available Build action calls the existing construction tool selection and retains rotation memory and placement behavior; locked machines show their existing requirement.

Version-2 progression saves add an optional `unseenDiscoveries` array alongside existing discovery records. The reader validates it as a unique subset of authored, already discovered recipes. Older saves without the field treat prior discoveries as viewed; new production after load still receives NEW. Unity Editor compilation, EditMode tests, and Play Mode appearance/input remain to be checked in the running Editor.

## UX-04 progression presentation

The Demo keeps compact active-order progress attached to the Market. Its click popover shows the current order, requirements, unlock rewards, and existing stage guidance; Seeds, Sales, and History switch to one separate detail view. Order completion captures the completed order and only newly granted unlocks before the next objective appears, queues one modal card per completion, and briefly labels the Market in world space. Orders have no separate currency bonus in the current data; delivery sales still appear as currency Toasts. Order unlock and completion Toasts are suppressed while the card covers those events.

`UnlockState` tracks unseen machine and crop keys. Build Menu, hotbar, Seed Shop, and crop picker display NEW until the specific item is selected. First selection shows brief guidance, and Help retains machine and crop guidance. Version-2 saves add an optional unseen-unlocks array. Older files without it treat existing unlocks as already viewed; new unlocks earned afterward become NEW. Saved unseen keys must be unlocked machine or crop keys.

Region selection lists progression, cardinal adjacency, current currency, and price independently, with guidance for each unmet condition. Purchase is disabled unless all gates pass. A successful purchase updates the existing region and currency state, closes the panel, sends the existing unlock Toasts, and briefly labels the restored land in world space. East Field now follows O3 Tomato Sauce; its Potato reward and provisional price are unchanged.

The Demo System Menu owns Save Game, confirmed Load Game, Resume, and confirmed Quit. There are no configurable settings to expose. Its saved-data summary reads the validated file's timestamp, active order ID, and restored-region count rather than live values. Save success closes the menu and emits the existing Toast; failure keeps it open. Load validates before replacing the world and uses the existing version-2 reconstruction path; reconstruction results appear as Toasts. Unity Editor compilation, EditMode tests, and Play Mode behavior remain to be checked in the running Editor.

## Milestone 04 construction and factory readability

`BuildingPlacementController` keeps normal building tools active after placement and stores the last `BuildingRotation` for each definition ID. R updates that remembered rotation. A new Farm Plot opens a crop picker and defaults to the crop last selected with that build tool. Belt and Pipe tools preview drag paths; Pipe validation uses a copy of the Property network and commits valid cells on release. Esc and right-click cancel active construction tools. Normal-mode right-click previews removable targets with a red outline and removes them on press or continuous drag; a cancel press cannot also remove a building. The Demo clipboard copies selected buildings and Property connections, preserves crop selection and group transforms, validates dependencies before paste, and commits cut only at a valid destination. Cut refuses buildings carrying active items; copied machines start with empty buffers. Fixed Property Sources and automatic Processor demands are not clipboard objects. Number-key selection continues through its existing path. Construction groups Demo options under Farming, Logistics, Manufacturing, and Property without changing the serialized option order or shortcuts. Locked machine buttons name the Market order that grants access. Invalid previews show actionable tooltips near the pointer, and adjacent port markers show connection compatibility.

Placed food machines display colored food input, food output, and property port markers; Mixer inputs and Cutter outputs are labeled A/B. UX-02 resolves internal state into player feedback: Working and Idle have no badge, while actionable problems show one `!`, an affected port or combination highlight, and a short action tooltip on hover. Clicking a problem temporarily emphasizes the port and an adjacent occupied connection. The F3 inspector retains internal state. Event Toasts report delivery currency, restoration unlocks, and successful saves without using machine stalls as events. Order completion rewards are now grouped into the UX-04 card. Transported food on belts uses provisional identity colors and two-letter labels, with a diamond for processed food. These visuals add no persisted state or recipe changes.

### Smart Belt routing

`BeltCell` retains placement rotation as its primary output and stores a four-bit cardinal output mask. Incoming connections are derived from neighboring output masks, so endpoints, straight runs, corners, T junctions, and four-way junctions use the same cell type. There are no independent crossing lanes. Drag interpolation still chooses each step's direction. A single new Belt prefers the unique incoming Belt's straight direction; ambiguous or absent incoming flow keeps the selected rotation, and an explicit R rotation takes precedence. Dragging across an existing Belt adds the explicitly dragged output without reversing primary flow; merely placing a neighbor does not create a side branch. Compatible incoming Belts and forward continuations connect through existing outputs. The preview and placed Belt draw colored connection arms; the primary arrow remains visible. At Far zoom structure remains visible while food identity detail is reduced.

`BeltTransportSystem.Advance` advances items to readiness, observes pre-transfer occupancy, proposes available masked outputs in round-robin order, arbitrates contended Belt destinations by each destination's incoming-direction cursor, then commits one transfer per source and destination. A rejected splitter can try another output in the same step. Successful transfers advance source output and destination input cursors. Blocked items stay in their cells, and receiver acceptance is checked before consumption. Single machine outputs compete for an empty Belt by output direction with a per-destination cursor in the later injection phase; paired outputs retain their all-or-nothing phase. Priority, filters, ratios, and independent crossings are not implemented; those can extend the masks and arbitration policy later without changing food identity or the Property network.

World saves keep `SavedBelt.outputMask` and both arbitration cursors beside food, entry direction, and progress. A zero mask from an older save means the rotation's single output. Construction history records mask changes and applies mask-only changes to existing Belts in place; each drag remains one history entry. Blueprint records retain each Belt mask and rotate or mirror its cardinal bits with the group. Demolition removes the cell and recalculates neighboring incoming display; upstream outputs remain explicit and safely stall when their target is gone. Empty output stubs can remain visible at line ends.

[`BuildingPlacementController.cs`](../Assets/_Project/Scripts/Buildings/BuildingPlacementController.cs) reserves the fixed Market cells in [`GridOccupancy.cs`](../Assets/_Project/Scripts/Buildings/GridOccupancy.cs). Its Harvester placement path permits an overlay only when the Farm Plot is present and the Harvester's other cell is free. The covered plot remains alive and configurable through [`ObjectivePanel.cs`](../Assets/_Project/Scripts/UI/ObjectivePanel.cs); removing the Harvester reveals it again. Demo group selection includes the Farm Plot beneath a Harvester; paste builds the plot before the Harvester and validates their relationship.

Farm Plot placement is limited to authored farmable cells in restored regions. [`FarmPlotPlacementBehavior.cs`](../Assets/_Project/Scripts/Food/FarmPlotPlacementBehavior.cs) checks region state before the normal occupancy check; other buildings retain their existing placement rules. The scene's provisional Starter Fields cover x **-5..4**, y **-4..4** and begin restored. East Field covers x **5..8**, y **-4..4** and begins locked. Existing placed buildings are not removed when region state changes. These rectangles are prototype map content, not the GDD's final farmland distribution or world generation.

The current sample values are **2 seconds** to grow one crop, **4** mature crops per plot, **1 second** between Harvester collections, **4** Harvester output slots, **1 second** for Processor completion, and **4** units of capacity per sample property source. Most sample foods sell for 1 regular currency; Potato Slice sells for 2 and French Fries for 3. Chapter 1 uses the eight-objective order sequence above. These are scene and prefab prototype settings, not finalized GDD balance or a general progression rule.

## Phase 2 property supply prototype

[`CookingPropertyNetwork.cs`](../Assets/_Project/Scripts/Food/CookingPropertyNetwork.cs) models Heat, Water, Time, and Cold separately from belt items. The enum retains numeric slots 0-3 in that order; old prototype slot 1 meant Moisture and slot 3 meant Air, so old save and Blueprint files are kept in their previous filenames rather than silently reinterpreted. Each grid connection belongs to one environmental source; collectors must touch that source, pipes extend through cardinal neighbors, and a connection cannot join two sources. The source's Inspector capacity is compared with connected demand. An overloaded network reports unavailable supply for all test endpoints because consumer allocation during shortages is still undecided. Removing a link recalculates live connectivity; disconnected sections retain their source owner.

[`PropertySupplyPlayMode.cs`](../Assets/_Project/Scripts/Food/PropertySupplyPlayMode.cs) provides property construction controls on the right side of the screen. Demo opens them from Construction and offers Collector, Pipe, and Remove. Select a source and the Collector tool, then click an adjacent cell. Pipe extends the network; Remove deletes placed connections. Green endpoints have available supply; red endpoints are disconnected or over capacity. Demo contains one sample node per property, each with a provisional capacity of four. All source and connection cells use `GridOccupancy`, so buildings and belts cannot be placed on them. Processor property demand attaches only to its rotated property-facing outside cell, counts against source capacity, and frees capacity on removal. Construction costs and final pipe controls remain open.

## Phase 2 Basic Mixer loop

[`BasicMixerPortLayout.cs`](../Assets/_Project/Scripts/Food/BasicMixerPortLayout.cs) defines the finalized 2×2 footprint: input A at (0,0) from West, input B at (0,1) from West, and output at (1,1) toward East, with all ports rotating with placement. ## Phase 3 orders and shared unlocks

[`FoodOrder.cs`](../Assets/_Project/Scripts/Food/FoodOrder.cs) defines serializable order requirements and generic unlock keys identified by category and ID. `FoodOrderSequence` activates authored orders in array order, one at a time. Each order snapshots Market delivery counts when activated, so earlier sales do not fill later orders; after completion it records the order once, grants its unlock keys to a shared `UnlockState`, and activates the next order. The Market exposes the authored orders, completed orders, active progress, and unlock state to the UI and future systems.

Demo authors the eight Chapter 1 objectives above. [`FarmPlot.cs`](../Assets/_Project/Scripts/Food/FarmPlot.cs) reads the shared unlock state when selecting crops, including on plots placed before an unlock. The Market panel displays active and completed orders and their unlocks. Array order remains the authored sequence. Order and unlock state can be restored through the Chapter 1 progression save.

## Farmable regions

`FarmableRegion` describes one authored rectangular patch of farmable cells. `RegionState` uses the shared `UnlockState` for restored region keys, exposes locked/restorable/restored status, and grants a region key once when the player restores an eligible region. The Market panel shows region names, cell bounds, price, and status. East Field requires O3 Tomato Sauce's access key and the authored currency price; other surrounding regions have their own provisional prices. Final requirements, costs, rewards, and map generation remain undecided. Restored region keys and remaining currency are included in the progression save.

## Basic Seed Shop

[`Market.cs`](../Assets/_Project/Scripts/Food/Market.cs) holds serialized seed offers and a `SeedShop` that reads the existing Market currency and shared `UnlockState`. An offer can require an unlock key before it is available. Its state is locked, available but unaffordable, affordable, purchased, or already unlocked through another source. A successful purchase spends currency once and grants a `crop` unlock; a failed or repeat purchase spends nothing. The Market panel displays these states and purchase buttons.

Chapter 1 has no Seed Shop offers. The generic Seed Shop system remains for later content; its saved purchased crop IDs and shared crop unlocks still use the same persistence path. Basil is not part of the Chapter 1 Farm Plot prefab or active objective rewards.

## Progression save

[`ProgressionSave.cs`](../Assets/_Project/Scripts/Food/ProgressionSave.cs) stores currency, cumulative food deliveries, completed order IDs, active order progress, shared unlock keys, purchased Seed Shop crop IDs, and discovered recipe identities. Version 2 also embeds [`FactoryWorldSnapshot.cs`](../Assets/_Project/Scripts/Food/FactoryWorldSnapshot.cs): placed building definition IDs, grid anchors and rotations; Farm Plot crop, mature count and growth time; Harvester ordered outputs and timer; belt food payload, entry direction and travel progress; Processor recipe inputs, property, output and elapsed time; Mixer slots and held output; and placed collectors, pipes and debug test loads with their source coordinates. Scene-authored property sources and automatic Processor demands are derived, not duplicated in the snapshot. Only stable IDs and grid coordinates are serialized.

Demo uses `Application.persistentDataPath/cozy-food-factory-demo.json`. Its path remains separate from the retired Prototype save file. The Demo System Menu provides manual Save and confirmed Load; Market no longer shows those actions. Save writes a temporary file and replaces the previous file only after writing and snapshot validation succeed. A version 1 progression-only file still loads from the active scene's path; the next successful save writes version 2. For version 2, Load validates the snapshot before reloading the current scene, restores progression, places Farm Plots before Harvester overlays, restores other equipment and property connections, then resumes production and transport. A reconstruction failure reloads a clean scene and displays an error. A missing or invalid file leaves the live session intact. Unsupported building IDs, non-food belt payloads, and Demo debug test demands are rejected rather than dropped. No autosave or save slots are defined by the GDD.

Unity `JsonUtility` writes unused inline building state classes as empty objects. On read, the snapshot codec collapses only the complete placeholder pattern for the four inactive state types (and empty food payloads) before strict validation. Nonempty mismatched state still fails with the building ID, cell, and state names in the error.

## Tests and next implementation boundary

[`Tests/EditMode/`](../Assets/_Project/Tests/EditMode/) contains focused tests for Farm Plot growth and region placement, restoration state, progression and world snapshot serialization, validation and version 1 migration, Harvester buffering and overlay placement, generic food transport, Market identity counts and currency spending, order progress and crop unlocking, Seed Shop availability and purchases, the plot-to-Market process chain, property network connectivity/capacity/isolation, Processor port rotation, Mixer port rotation and input ownership, recipe matching, discovery deduplication and popup queue behavior, and held output. These are Unity EditMode tests; compilation alone does not establish that they ran. The scene's full Play Mode loop requires manual verification in the running Editor.

Before extending food machines, account for these observed boundaries:

- `FoodItemData` stores ID and kind. Processing recipes match this identity with one property; there is no multi-property runtime model.
- [`BeltTransportSystem.cs`](../Assets/_Project/Scripts/Logistics/BeltTransportSystem.cs) maps one receiver to each input cell and reserves transfers per step. The Basic Mixer uses two cell receivers with a shared per-step reservation, so only one ingredient enters it per transport step. Invalid or ambiguous second ingredients remain on their belts.
- Food belts and property supply use separate models. The Processor uses the finalized first port layout. Property shortage allocation and intersection rules remain undecided; over-capacity supply currently reports unavailable to connected demands.
- Belt's serialized debug field still reflects rune origins. Food item visuals support optional Sprites and color/shape/label fallbacks.
- Demo authors five delivery orders with a restoration gate between the third and fourth. Version 2 reconstructs the food world through a scene reload; Unity Play Mode verification is still required. A final rule for linking restoration to shop availability also needs separate design and implementation.
- Currency buys authored region purchases. Chapter 1 has no Seed Shop offer. Farm Plot placement is restricted to restored authored farmable rectangles, while other building placement remains unrestricted by regions.
