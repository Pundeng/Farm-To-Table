# Cozy Food Factory implementation map

This document describes the current Unity **6000.5.2f1** implementation. The [Cozy Food Factory GDD](COZY_FOOD_FACTORY_GDD.md) describes intended rules; this map records what the repository currently does. `Demo.unity` is the food-only playable scene; `Prototype.unity` remains for legacy rune regression.

## UX-04 progression presentation

The Demo keeps compact active-order progress attached to the Market. Its click popover shows the current order, requirements, unlock rewards, and existing stage guidance; Seeds, Sales, and History switch to one separate detail view. Order completion captures the completed order and only newly granted unlocks before the next objective appears, queues one modal card per completion, and briefly labels the Market in world space. Orders have no separate currency bonus in the current data; delivery sales still appear as currency Toasts. Order unlock and completion Toasts are suppressed while the card covers those events.

`UnlockState` tracks unseen machine and crop keys. Build Menu, hotbar, Seed Shop, and crop picker display NEW until the specific item is selected. First selection shows brief guidance, and Help retains machine and crop guidance. Version-2 saves add an optional unseen-unlocks array. Older files without it treat existing unlocks as already viewed; new unlocks earned afterward become NEW. Saved unseen keys must be unlocked machine or crop keys.

Region selection lists progression, cardinal adjacency, current currency, and price independently, with guidance for each unmet condition. Purchase is disabled unless all gates pass. A successful purchase updates the existing region and currency state, closes the panel, sends the existing unlock Toasts, and briefly labels the restored land in world space. East Field's Vegetable Base gate, Potato reward, and Demo prices are unchanged.

The Demo System Menu owns Save Game, confirmed Load Game, Resume, and confirmed Quit. There are no configurable settings to expose. Its saved-data summary reads the validated file's timestamp, active order ID, and restored-region count rather than live values. Save success closes the menu and emits the existing Toast; failure keeps it open. Load validates before replacing the world and uses the existing version-2 reconstruction path; reconstruction results appear as Toasts. Prototype retains its legacy Market Save/Load controls because it has no Demo System Menu. Unity Editor compilation, EditMode tests, and Play Mode behavior remain to be checked in the running Editor.

## Milestone 04 construction and factory readability

`BuildingPlacementController` keeps normal building tools active after placement and stores the last `BuildingRotation` for each definition ID. R updates that remembered rotation. A new Farm Plot opens a crop picker and defaults to the crop last selected with that build tool. Belt and Pipe tools preview drag paths; Pipe validation uses a copy of the Property network and commits valid cells on release. Esc and right-click cancel active construction tools. Normal-mode right-click previews removable targets with a red outline and removes them on press or continuous drag; a cancel press cannot also remove a building. The Demo clipboard copies selected buildings and Property connections, preserves crop selection and group transforms, validates dependencies before paste, and commits cut only at a valid destination. Cut refuses buildings carrying active items; copied machines start with empty buffers. Fixed Property Sources and automatic Processor demands are not clipboard objects. Number-key selection continues through its existing path. Construction groups Demo options under Farming, Logistics, Manufacturing, and Property without changing the serialized option order or shortcuts. Locked machine buttons name the Market order that grants access. Invalid previews show actionable tooltips near the pointer, and adjacent port markers show connection compatibility.

Placed food machines display colored food input, food output, and property port markers; Mixer inputs and Cutter outputs are labeled A/B. UX-02 resolves internal state into player feedback: Working and Idle have no badge, while actionable problems show one `!`, an affected port or combination highlight, and a short action tooltip on hover. Clicking a problem temporarily emphasizes the port and an adjacent occupied connection. The F3 inspector retains internal state. Event Toasts report delivery currency, restoration unlocks, and successful saves without using machine stalls as events. Order completion rewards are now grouped into the UX-04 card. Transported food on belts uses provisional identity colors and two-letter labels, with a diamond for processed food. These visuals add no persisted state or recipe changes.

## Milestone 03 land expansion

`Demo.unity` authors four locked surrounding rectangles beside the restored Starter Fields. East Field remains gated by the Vegetable Base order and grants Potato on restoration. The new West Meadow, North Terrace, and South Orchard have no progression prerequisite. The demo prices are **provisional**: East Field 5, West Meadow 3, North Terrace 4, South Orchard 4 regular currency. Every cell inside each authored rectangle is designated farmable; ground outside is not. Prototype retains its older region definitions and free restoration for regression compatibility.

`RegionState` requires a shared cardinal edge with an already restored region, the authored progression unlock, and sufficient `MarketInventory` currency for a purchase. A successful purchase records the existing region unlock, applies restoration rewards once, and spends currency once. `MarketPanel` renders tinted region backgrounds behind the grid and a map-selected region panel with bounds, price, status, progression requirement, farmable-cell capacity, and a purchase control. Locked regions can be selected by clicking empty cells; restored regions can be inspected from the Market list or by Alt-clicking empty cells. The panel consumes its own pointer input, while clicks on occupied cells still reach building interaction. Non-farmable ground uses the dark map background. Farm Plot previews label locked, non-farmable, and occupied failures.

The existing version-2 save stores remaining currency, region unlocks, and placed Farm Plots. Loaded regions and capacity are derived from those values; no new serialized save field is needed. EditMode tests cover purchase gates, cardinal adjacency, click routing, placement restrictions, and a purchased-region progression round trip. Unity Editor compilation, EditMode execution, and Play Mode appearance/input remain to be checked in the running Editor.

## Milestone 02 demo progression

`Demo.unity` authors five sequential, Inspector-editable delivery orders: 3 Apples, 2 Dried Apples, 2 Vegetable Base, 2 Cut Potatoes, and 2 French Fries. Their rewards unlock Processor and Onion, then Mixer and Tomato, then Cutter and East Field restoration access. Restoring East Field grants Potato through `RegionState`; the active Cut Potato order guides that restoration before cutting. The final order grants `demo/complete`, shown as Demo Complete in the Market panel. The optional Basil Seed Shop remains unlocked by the Apple order. Quantities, durations, and prices are provisional scene and prefab values.

Demo uses [`DemoFarmPlot.prefab`](../Assets/_Project/Prefabs/DemoFarmPlot.prefab), which keeps Tomato locked until the Dried Apple order and adds Potato as a crop locked until East Field restoration. Prototype continues to use its original Farm Plot prefab and order content. Construction shows locked Processor, Mixer, and Cutter buttons until the corresponding `machine` unlock. The Market panel supplies stage-specific directions for food and property ports.

[`Cutter.cs`](../Assets/_Project/Scripts/Food/Cutter.cs), [`CutterProcess.cs`](../Assets/_Project/Scripts/Food/CutterProcess.cs), and [`CutterPortLayout.cs`](../Assets/_Project/Scripts/Food/CutterPortLayout.cs) implement the rotatable 1×2 Cutter: one rear food input and two lateral outputs at the front. The sole authored cutting recipe is Potato → two Cut Potatoes. A valid input can wait in the Cutter buffer; both output belts must be free before the cycle starts or advances. [`IItemOutputPairSource.cs`](../Assets/_Project/Scripts/Logistics/IItemOutputPairSource.cs) lets the belt system preflight both belts and transfer both products in one step. A blocked output leaves the cycle or completed pair held; each unavailable port has a red marker. Cutter state, its recipe discovery, and Cut Potato/French Fries food identity participate in the version-2 save and scene validation. Processor also authors Cut Potato + Heat → French Fries.

Old Milestone 01 Demo saves are migrated in memory on load: a completed First Harvest order opens Dried Apples, and missing Processor or restored-region Potato unlocks are added. A previously selected Tomato crop retains its unlock. The existing file changes only after the player explicitly saves. Old saves may retain East Field access granted by Milestone 01 before the new Vegetable Base gate; that legacy reward is preserved. Prototype saves retain their separate path and scene behavior.

## Phase 1 food loop

`Demo.unity` copies the food systems, Market, property sources, recipes, crop/seed offers, and region definitions from `Prototype.unity`. Its construction panel offers Belt, Farm Plot, Harvester, Processor, Basic Mixer, and Cutter; a Property connections button opens Collector, Pipe, and Remove controls. F8 and the test-load tool remain exclusive to Prototype. Demo has no Hub, rune deposits, RuneResourceMap, rune placement options, or rune objectives. The machine configuration panel is attached to Building Placement without a Hub reference.

Its Harvester placement path permits an overlay only when the Farm Plot is present and the Harvester's other cell is free. The covered plot remains alive and configurable through [`ObjectivePanel.cs`](../Assets/_Project/Scripts/UI/ObjectivePanel.cs); removing the Harvester reveals it again. Demo group selection includes the Farm Plot beneath a Harvester; paste builds the plot before the Harvester and validates their relationship. The legacy Prototype move path retains its move-state restriction.

Farm Plot placement is limited to authored farmable cells in restored regions. [`FarmPlotPlacementBehavior.cs`](../Assets/_Project/Scripts/Food/FarmPlotPlacementBehavior.cs) checks region state before the normal occupancy check; other buildings retain their existing placement rules. The scene's provisional Starter Fields cover x **-5..4**, y **-4..4** and begin restored. East Field covers x **5..8**, y **-4..4** and begins locked. Existing placed buildings are not removed when region state changes. These rectangles are prototype map content, not the GDD's final farmland distribution or world generation.

The current sample values are **2 seconds** to grow one crop, **4** mature crops per plot, **1 second** between Harvester collections, **4** Harvester output slots, **1 second** for Processor completion, **4** units of capacity per sample property source, and **1** regular currency per sample food delivery. Prototype's first order asks for **3 apples** and directly unlocks Onion; Demo uses the five-stage order sequence above. These are scene and prefab prototype settings, not finalized GDD balance or a general progression rule.

## Phase 2 property supply prototype

[`CookingPropertyNetwork.cs`](../Assets/_Project/Scripts/Food/CookingPropertyNetwork.cs) models Heat, Moisture, Time, and Air separately from belt items. Each grid connection belongs to one environmental source; collectors must touch that source, pipes extend through cardinal neighbors, and a connection cannot join two sources. The source's Inspector capacity is compared with connected demand. An overloaded network reports unavailable supply for all test endpoints because consumer allocation during shortages is still undecided. Removing a link recalculates live connectivity; disconnected sections retain their source owner.

[`PropertySupplyPlayMode.cs`](../Assets/_Project/Scripts/Food/PropertySupplyPlayMode.cs) provides property construction controls on the right side of the screen. Demo opens them from Construction and offers Collector, Pipe, and Remove. Prototype still opens them with F8 and includes the developer Test load tool. Select a source and the Collector tool, then click an adjacent cell. Pipe extends the network; Remove deletes placed connections. Green endpoints have available supply; red endpoints are disconnected or over capacity. Both scenes contain one sample node per property, each with a provisional capacity of four. All source and connection cells use `GridOccupancy`, so buildings and belts cannot be placed on them. Processor property demand attaches only to its rotated property-facing outside cell, counts against source capacity, and frees capacity on removal. Construction costs and final pipe controls remain open.

## Phase 2 Processor loop

Prototype's key **7** and Demo's key **4** uses the finalized three-cell Processor footprint: chamber (0, 1), property module (1, 1), and lower support (0, 0); (1, 0) remains open. [`ProcessorPortLayout.cs`](../Assets/_Project/Scripts/Food/ProcessorPortLayout.cs) rotates the cells and three ports together. A belt enters from the chamber's West side in the default orientation, a pipe connects at the property module's South side through the open corner, and a finished-food belt begins beyond the chamber's North side. The controller installs [`ProcessorPlacementBehavior.cs`](../Assets/_Project/Scripts/Food/ProcessorPlacementBehavior.cs) for that scene option at runtime; the behavior initializes [`Processor.cs`](../Assets/_Project/Scripts/Food/Processor.cs) and registers food input/output with the existing belt coordinator.

[`ProcessingRecipe.cs`](../Assets/_Project/Scripts/Food/ProcessingRecipe.cs) matches food identity and one supplied property. [`ProcessorProcess.cs`](../Assets/_Project/Scripts/Food/ProcessorProcess.cs) accepts food only for exactly one matching recipe, pauses if the active property supply is lost, and holds finished output until a belt can take it. The scene has one provisional recipe, Apple + Air → Dried Apple, and a provisional one-second processing duration. In Demo, hovering a stalled Processor shows the affected port and an action; clicking it briefly emphasizes the port and adjacent connection. Prototype retains its configuration panel. Compost and final balance are not part of this loop.

## Phase 2 Basic Mixer loop

[`BasicMixerPortLayout.cs`](../Assets/_Project/Scripts/Food/BasicMixerPortLayout.cs) defines the finalized 2×2 footprint: input A at (0,0) from West, input B at (0,1) from West, and output at (1,1) toward East, with all ports rotating with placement. [`BasicMixer.cs`](../Assets/_Project/Scripts/Food/BasicMixer.cs) registers two separate food receivers and one output source with the existing belt coordinator. The two receivers share a per-step reservation, so simultaneous belt arrivals are accepted one at a time and the second can be checked against the first ingredient. [`MixingRecipe.cs`](../Assets/_Project/Scripts/Food/MixingRecipe.cs) matches unordered food pairs; [`BasicMixerProcess.cs`](../Assets/_Project/Scripts/Food/BasicMixerProcess.cs) accepts a second ingredient only for one unique recipe and holds its output until a belt is available. Prototype's key **8** and Demo's key **5** has the GDD's provisional Tomato + Onion → Vegetable Base recipe; the Farm Plot prefab offers Tomato and Onion for this loop. The Mixer has no property-network input.

## Phase 3 recipe discovery tracking

[`RecipeDiscoveryRegistry.cs`](../Assets/_Project/Scripts/Food/RecipeDiscoveryRegistry.cs) records the first completed production of each processing or mixing recipe. The Processor records when its timer completes; the Mixer records when its second ingredient creates output. The placement controller shares one registry across both machine types and exposes its read-only discovered recipe list and first-discovery event. [`RecipeDiscoveryPanel.cs`](../Assets/_Project/Scripts/UI/RecipeDiscoveryPanel.cs) uses that event for a dismissible first-discovery popup and reads the live list for a minimal Recipe Book. The recipe's output food ID serves as its display name. Discovered recipe identities are included in the progression save; the GDD's full discovery animation is not implemented.

## Phase 3 orders and shared unlocks

[`FoodOrder.cs`](../Assets/_Project/Scripts/Food/FoodOrder.cs) defines serializable order requirements and generic unlock keys identified by category and ID. `FoodOrderSequence` activates authored orders in array order, one at a time. Each order snapshots Market delivery counts when activated, so earlier sales do not fill later orders; after completion it records the order once, grants its unlock keys to a shared `UnlockState`, and activates the next order. The Market exposes the authored orders, completed orders, active progress, and unlock state to the UI and future systems.

Prototype currently authors only the existing provisional order: deliver three apples to grant the `crop` / `Onion` key, make Basil seeds available in the shop, and make East Field restorable. [`FarmPlot.cs`](../Assets/_Project/Scripts/Food/FarmPlot.cs) reads the shared unlock state when selecting crops, including on plots placed before an unlock. The Market panel displays active and completed orders and their unlocks without naming specific foods. Additional orders can be authored, but their content, rewards, and final activation policy remain undecided; array order is the prototype continuation of the former single active order. The direct Onion grant preserves prototype behavior. Order and unlock state can be restored through the manual progression save.

## Farmable regions

`FarmableRegion` describes one authored rectangular patch of farmable cells. `RegionState` uses the shared `UnlockState` for restored region keys, exposes locked/restorable/restored status, and grants a region key once when the player restores an eligible region. The Market panel shows region names, cell bounds, and status, with a Restore button when a region is eligible. East Field requires the Apple order's `region_access` / `East Field` key; restoration has no currency cost in this slice. The GDD leaves exact requirements, costs, rewards, and map generation undecided. Restored region keys are included in the progression save.

## Basic Seed Shop

[`Market.cs`](../Assets/_Project/Scripts/Food/Market.cs) holds serialized seed offers and a `SeedShop` that reads the existing Market currency and shared `UnlockState`. An offer can require an unlock key before it is available. Its state is locked, available but unaffordable, affordable, purchased, or already unlocked through another source. A successful purchase spends currency once and grants a `crop` unlock; a failed or repeat purchase spends nothing. The Market panel displays these states and purchase buttons.

Both scenes offer provisional **Basil Seeds** for **3 regular currency**, made available by the existing Apple order. The Farm Plot prefab includes Basil as a locked crop. The GDD intends region restoration before shop availability; both scenes still grant shop availability directly from the Apple order, while East Field restoration is a separate action. The Basil crop, price, growth duration, and reward are sample content, not final balance or progression design. Seed purchases unlock crop selection rather than consuming currency for each planting. Purchased crop IDs and the shared crop unlocks are included in the progression save.

## Progression save

[`ProgressionSave.cs`](../Assets/_Project/Scripts/Food/ProgressionSave.cs) stores currency, cumulative food deliveries, completed order IDs, active order progress, shared unlock keys, purchased Seed Shop crop IDs, and discovered recipe identities. Version 2 also embeds [`FactoryWorldSnapshot.cs`](../Assets/_Project/Scripts/Food/FactoryWorldSnapshot.cs): placed building definition IDs, grid anchors and rotations; Farm Plot crop, mature count and growth time; Harvester ordered outputs and timer; belt food payload, entry direction and travel progress; Processor recipe inputs, property, output and elapsed time; Mixer slots and held output; and placed collectors, pipes and debug test loads with their source coordinates. Scene-authored property sources and automatic Processor demands are derived, not duplicated in the snapshot. Only stable IDs and grid coordinates are serialized.

Prototype uses `Application.persistentDataPath/cozy-food-factory-progress.json`; Demo uses `Application.persistentDataPath/cozy-food-factory-demo.json`, so Demo saves do not overwrite existing Prototype saves. The Demo System Menu provides manual Save and confirmed Load; Market no longer shows those actions. Save writes a temporary file and replaces the previous file only after writing and snapshot validation succeed. A version 1 progression-only file still loads from the active scene's path; the next successful save writes version 2. For version 2, Load validates the snapshot before reloading the current scene, restores progression, places Farm Plots before Harvester overlays, restores other equipment and property connections, then resumes production and transport. A reconstruction failure reloads a clean scene and displays an error. A missing or invalid file leaves the live session intact. Legacy rune buildings, RuneData on belts, active Hub progress, and Demo debug test demands are rejected rather than dropped. No autosave or save slots are defined by the GDD.

Unity `JsonUtility` writes unused inline building state classes as empty objects. On read, the snapshot codec collapses only the complete placeholder pattern for the four inactive state types (and empty food payloads) before strict validation. Nonempty mismatched state still fails with the building ID, cell, and state names in the error.

## UI input boundary

Market detail views scroll within the lower left of the screen; the current-order popover stays near the Market. Their pointer areas block world placement and camera wheel zoom. The Recipe Book and discovery popup block world placement, and the Recipe Book blocks camera wheel zoom while hovered. The machine configuration panel blocks world placement when hovered, including clicks on crop selection buttons. Demo's construction panel and the property panel also block world placement while hovered. The property panel uses the same top-origin pointer coordinates as its IMGUI rectangle. These panels still use fixed screen positions, so narrow windows may overlap; responsive layout is not implemented.

## Tests and next implementation boundary

[`Tests/EditMode/`](../Assets/_Project/Tests/EditMode/) contains focused tests for Farm Plot growth and region placement, restoration state, progression and world snapshot serialization, validation and version 1 migration, Harvester buffering and overlay placement, generic food transport, Market identity counts and currency spending, order progress and crop unlocking, Seed Shop availability and purchases, the plot-to-Market process chain, property network connectivity/capacity/isolation, Processor port rotation, Mixer port rotation and input ownership, recipe matching, discovery deduplication and popup queue behavior, and held output. These are Unity EditMode tests; compilation alone does not establish that they ran. The scene's full Play Mode loop requires manual verification in the running Editor.

Before extending food machines, account for these observed boundaries:

- `FoodItemData` stores ID and kind. Processing recipes match this identity with one property; there is no multi-property runtime model.
- [`BeltTransportSystem.cs`](../Assets/_Project/Scripts/Logistics/BeltTransportSystem.cs) maps one receiver to each input cell and reserves transfers per step. The Basic Mixer uses two cell receivers with a shared per-step reservation, so only one ingredient enters it per transport step. Invalid or ambiguous second ingredients remain on their belts.
- Legacy Engraver and Element Infuser recipes operate on `RuneData` and require manual configuration. They are not an implementation of the GDD's automatic food recipe matching.
- Food belts and property supply use separate models. The Processor uses the finalized first port layout. Property shortage allocation and intersection rules remain undecided; over-capacity supply currently reports unavailable to connected demands.
- Belt carrier and debug names still reflect rune origins. Food uses the same placeholder belt item visual, so distinct food identities are visible through debug text and Market counts rather than item art.
- Prototype authors one order; Demo authors five delivery orders with a restoration gate between the third and fourth. Version 2 reconstructs the food world through a scene reload; Unity Play Mode verification is still required. A final rule for linking restoration to shop availability also needs separate design and implementation.
- Currency now buys the provisional Basil seed unlock; food construction, upgrades, and land purchases do not consume it. Farm Plot placement is restricted to the two authored farmable rectangles when restored, while other building placement remains unrestricted by regions.
